# متى نعيد مراجعة الاستراتيجية بعد تحديث الأدلة؟

بدأ القياس على `codex/profile-refresh-review` عند `f5ee690`. ثُبّت [البروتوكول](PROTOCOL.md) و[التصنيف المتوقع](labels.json) قبل تشغيل المرشح. وحدة القياس زوج نسخ مع ادعاء أو جزء استراتيجي محدد. حسبنا كل زوج باعتباره تحديثًا أدى إلى حفظ بروفايل جديد، وهي نقطة تطبيق السياسة الحالية.

## المقارنة

| العينة | مراجعات السياسة الحالية | زائدة يمكن تفاديها من إجمالي الزائدة | تغييرات مؤثرة كانت ستمر من إجمالي المؤثرة | غير محسومة في الظل |
|---|---:|---:|---:|---:|
| نسخ عامة متعاقبة | 8/8 | 1/4 | 0/4 | 0/8 |
| حالات مصطنعة معلّمة | 12/12 | 1/3 | 1/7 | 2/12 |
| **المجموع** | **20/20** | **2/7** | **1/11** | **2/20** |

السياسة الحالية سجّلت في المحاكاة 7 مراجعات زائدة وصفر تغييرات مؤثرة فائتة. المرشح قال مراجعة في 15 حالة، وتجاوز افتراضي في 3، وغير محسوم في 2. نحسب غير المحسوم كاستمرار للمراجعة. الحالتان غير المحسومتين هما تعذّر التقاط مصدر، ووجود دليل من صفحة خارج التغطية. ظلّت خمس مراجعات زائدة مطلوبة في المرشح، منها تبدّل ترتيب الصفحة وتغيير تنسيقها وتصحيح رابط. [المخرجات والأسباب لكل حالة](comparison.json)

- **المراجعة ضرورية** عند تغيّر السعر أو الفرع أو مدة العرض أو ظهور استثناء يؤثر في نطاق الوعد. المرشح رصد تغير الصفحة في حالات السعر والفرع وإزالة العرض، ورصد الاستثناء المصطنع على الصفحة نفسها أو على صفحة شروط ملتقطة حتى مع بقاء الاقتباس. في البيانات العامة، بقي مطلع الاقتباس عن حد أسماء الشهادة كما هو، وأصبح الحد مشروطًا بنوع ملف الشهادة. [تغيير شرط ملف الشهادة في مستودع Let’s Encrypt](https://github.com/letsencrypt/website/commit/6ccb286fed2ba6fd5d768a576f315c4efb795d6b)
- **المراجعة زائدة** في حالة ثبات الادعاء وقيوده. تخطّى المرشح تحديثين تطابق فيهما المستند الملتقط. أعاد طلبها عند نقل فقرة بحث في توثيق حد الشهادات، وعند تغيير مرساة رابط في توثيق GitHub Pages. [نقل الفقرة](https://github.com/letsencrypt/website/commit/225986dfb2766be7c981d3fb2976a26878e9f743)، [تحديث الرابط في GitHub Docs](https://github.com/github/docs/blob/2c6caa0863fe281adfe47a1810c5e991008686e7/content/pages/getting-started-with-github-pages/github-pages-limits.md)
- **الإخفاق المؤثر** عرض مصطنع انتهى بينما الصفحة والاقتباس ظلا مطابقين. المرشح يقرأ بصمة المحتوى فيفوت انتهاء الصلاحية بمرور الوقت وحده.

## ما نُفّذ في ADZY

مسار الكشط يجمع بصمة HTML الملتقط والمواد القادمة عبر API من manifest نفس المهمة في الذاكرة. يحفظها في Run الكشط. عند تحديث براند له استراتيجية معتمدة، يقارن ببروفايل تلك الاستراتيجية، ويحفظ القرار والأسباب وبصمات الصفحات المتغيرة ومعرّفات الاقتباسات في Run التحديث. أُعيدت مقارنة تحديث ثالث مطابق للثاني بالبروفايل المعتمد الأول. مصدر غير متاح أو التقاط غير قابل للمقارنة قد ينتج `UNKNOWN`، وفشل مقارنة داخل قاعدة البيانات معزول عن حفظ البروفايل.

واجهة الاستراتيجية تعرض نتيجة الظل والجزء المرتبط بالدليل. في الديمو يظهر **Reason to believe** بجوار الاقتباس السابق عن عملية بدء الخدمة والاقتباس الجديد عن قائمة التحقق. تجمّع الواجهة الاقتباسات التي بقيت ظاهرة في تفاصيل يمكن فتحها. اختبار Chromium أثبت أن `SKIP` في الظل ما زال يعيد `409` لعقد البوستر القديم. بعد تغير الدليل وإعادة تشغيل الخادم ظهر نفس الربط، ثم اكتملت إعادة اعتماد SWOT والاستراتيجية. سجّل الديمو صفر أخطاء صفحة وصفر إرسال لمزود مدفوع، في 46.57 ثانية شاملة تحميل الصفحات وإعادة التشغيل. ## حدود الحكم

العينة صغيرة وموجهة وسبعة من الأزواج العامة الثمانية من موقع واحد. أُعيد تنزيل 13 نسخة ملف فريدة من معرّفات Git ثابتة، وتحققت البصمات والاقتباسات الأصلية. تلك النسخ ملفات مصدر الناشر، بينما التقاط التطبيق الحي يعتمد على DOM ومواد API المشاهدة. تصنيف الأثر من الوكيل بعد فحص الفروق وقبل المقارنة، ومقاس على الادعاءات المحددة للحالات. صلاحية العرض، ما وراء نطاق الكشط، والموارد الخارجية التي لا تدخل الالتقاط تحتاج أدلة إضافية. نحو نصف مللي ثانية هو زمن دالة المقارنة لـ20 زوجًا بعد تجهيز البصمات. زمن الكشط الفعلي وتكلفة المراجعة البشرية غير مقاسين. الصرف الخارجي 0 دولار.

**قرار التفعيل** السياسة تبقى في الظل. حالة انتهاء العرض وحدها تثبت حاجة بيانات الصلاحية، والعينة العامة لا تكفي لتقدير معدل الخطأ قبل التفعيل.

## إعادة التشغيل

من جذر الفرع، في بيئة اعتماديات التطبيق:

```bash
python tools/measure_review_shadow.py --output /tmp/adzy-review-shadow.json
python tools/measure_review_shadow.py --verify-public --output /tmp/adzy-review-shadow-verified.json
run_dir=$(mktemp -d)
python tools/verify_profile_refresh_browser.py --directory "$run_dir/demo" --evidence-dir "$run_dir/evidence"
python -m workflows.verify -q tests/test_review_shadow.py
```

الأمر الأول يعيد المقارنة دون شبكة. الثاني يعيد قراءة ملفات المصدر العامة ويتحقق من البصمات والاقتباسات. الديمو يستخدم Docker وصورة `postgres:16-alpine` وPlaywright Chromium، مع صفحة موقع ومزود اصطناعيين.

## التحقق الهندسي

نجحت المجموعة المركزة بـ81 اختبار Python، منها خمسة لمسار الظل وتجميع البصمات. شغّلنا أيضًا 21 اختبار Node و3 اختبارات لحزمة المصدر. اختبرت PostgreSQL مقارنة الالتقاط نفسه بعد حفظ نسخة جديدة، وحجب التوليد والاعتماد القديم، وخصوصية العرض، والتعامل مع فشل استعلام المقارنة. أُعيد اختبار واجهة المتصفح بعد تصحيح محدد اقتباس كان يبحث داخل عنصر غير مناسب. وفي تجميع اختبارات PostgreSQL احتفظت fixture بوصلة لحاوية سابقة، فصُحّح تنظيف مصنع الجلسات واجتازت المجموعة نفسها. التقييم الكامل للمشروع غير مشغّل.
